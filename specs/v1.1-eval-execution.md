# v1.1 milestone — activate eval execution (runner + judge) & close forward-compat debts

> **Status:** roadmap / forward-looking design. Nothing here is implemented yet — v1 shipped the *dormant* substrate; v1.1 makes eval execution live. ## Why v1.1

v1 deliberately shipped the eval-scoring machinery **dormant**:
- `evals/runner.py` `HarnessRunner.run_task` and `evals/judge.py` `Judge.score` are placeholder ABCs that raise `NotImplementedError` (SPEC §15.3).
- `playbook eval` is list/show-only (SPEC §12.8); nothing executes a task against an agent.
- The unified `Evaluator` registry (PR M) can already *compile* a task's blocks — `evals/task.py::evaluators_for_task` turns `[metrics]`→static+execution evaluators and `[rubric]`→`JudgedCriterion` — but nothing *runs* them, and `JudgedCriterion.available()` is `False` without a `ctx.judge`.

**v1.1 turns the key:** implement the runner + judge so an eval task is executed end-to-end and scored across all three layers (`[expected]` file checks · `[metrics]` non-regression · `[rubric]` judged) through the *same* `grade()` gate + weighted composite. It also pays down the two known forward-compat debts (the `Judge.score` signature, `[expected]`→bool) and the one cleanup chip (TOML serializer DRY).

## R1 — the runner (`HarnessRunner`)

`run_task(task, runner_cfg) -> TaskResult`:
1. **Materialize** a scratch repo from `task.setup/` (files + mocked detector facts), isolated per run (temp dir / `git init` so execution-evaluator baselines work).
2. **Drive the agent** via a per-assistant concrete runner (SPEC §15.3 names `ClaudeCodeRunner`, `ContinueCLIRunner`, `OpenCodeRunner`) using `task.invocation` (the slash prompt + `input_variables`); capture the modified tree, the transcript, and `scratch_dir_state`.
3. **Score** by compiling `evaluators_for_task(task, task.metrics)` and running each evaluator the `EvalContext` makes available:
   - **`[expected]`** file checks → `CheckResult`s (or BOOL evaluators once R3 lands).
   - **`[metrics]`** static evaluators on the output tree; execution evaluators (`test_pass_rate`, `coverage`) run the suite on `setup/` (baseline) and output (candidate) → `grade()` non-regression (deterministic exact `max_worsening=0`) + absolute on new scopes.
   - **`[rubric]`** `JudgedCriterion`s via `ctx.judge` (R2).
4. **Aggregate:** `grade()` → an `EvaluationReport` per layer; the **gate** = all deterministic (`[expected]` + deterministic `[metrics]`) pass; the **composite** = weighted `to_score()` across all weighted evaluators (static + execution + judged). `TaskResult` carries gate + composite + per-finding detail.

**Routing by capability:** the runner sets `EvalContext.{module, source, label, project, judge, artifact, samples}`; each evaluator's `available(ctx)` decides if it runs (static always; execution iff `project`; judged iff `judge`). A run with no judge configured scores deterministic-only — the air-gapped default.

## R2 — the judge + the signature reconciliation (headline debt)

**The mismatch (SPEC §21.2.3):** the v2 ABC is `Judge.score(rubric: Rubric, transcript: str, scratch_dir_state: dict) -> list[float]` (whole-rubric, batch). But `JudgedCriterion.evaluate()` duck-types a **per-criterion** call `ctx.judge.score(self.criterion, ctx.artifact, n=ctx.samples) -> float`. These cannot both be the live interface.

**Recommended reconciliation:** make the per-criterion call the primitive and keep batch as sugar:
- Define the judge protocol `ctx.judge` consumes as **`score_criterion(criterion: str, artifact, n: int) -> float`** (averages `n` samples internally; this is what `JudgedCriterion` already calls, modulo the method name).
- Re-express the batch `Judge.score(rubric, transcript, scratch_dir_state)` as a thin wrapper that maps each rubric line through `score_criterion` (with the transcript/scratch state passed as the artifact/context), returning the per-criterion `list[float]` — preserving the existing ABC signature for any batch caller while giving `JudgedCriterion` a typed primitive.
- Replace `JudgedCriterion`'s duck-typed `Any` judge with this typed protocol; `available()` stays `ctx.judge is not None`.
- Concrete impls: **`LLMJudge`** (strong model, calibrated grading prompt, n-sample averaging — **network-dependent, opt-in**) and **`ProgrammaticOnlyJudge`** (returns no judged scores so aggregation falls back to deterministic-only — the **air-gapped default**, SPEC §15.3).

Decision to confirm at implementation time: method name (`score_criterion` vs overload `score`) and whether the batch wrapper or the per-criterion primitive is canonical. Either way, **the v1 dormant API must keep working** — `JudgedCriterion` was built against the per-criterion shape, so the primitive should match it.

## R3 — `[expected]`→bool evaluators + execution wiring

- Extend `evaluators_for_task` to compile `[expected]` into BOOL deterministic evaluators (`file_exists`, `file_contains` regex, `file_unchanged`, `file_forbidden`) so the three layers unify under one `grade()`/composite. (v1 deliberately deferred this — `task.py::evaluators_for_task` docstring; `ExpectedOutcome` file-checks currently stay separate.) Alternative: keep `ExpectedOutcome` as-is and merge its `CheckResult`s into the report — pick one; unifying is cleaner.
- Wire execution evaluators into the runner's two-run non-regression (baseline `setup/` vs candidate output) using the existing `ProjectHandle`.

## R4 — shared TOML serializer (cleanup chip `task_56e8dcc5`)

`harness/manifest.py` and `sources/filesystem.py` hand-roll near-identical TOML scalar/string/key escaping. Extract the shared formatters into one module (e.g. `_toml.py`), parameterizing inline-dict support (manifest needs it; the flat Config/Lockfile writer doesn't), and import from both. Behaviour-preserving; net ~30 LoC removed.

## CLI & invariants

- **CLI:** `playbook eval <id> --run [--judge <name>] [--samples N] [--run-tests]` executes a task and prints the gate + composite + findings; v1's `--list`/`--show` stay.
- **Air-gapped:** `ProgrammaticOnlyJudge` is the default (no network); `LLMJudge` is opt-in. Execution evaluators still shell out to the target's pytest (no playbook dep). radon stays the only optional extra.
- **Forward-compat discipline:** v1.1 must not break the v1 public surface — the `Evaluator`/`grade`/`evaluators_for_task` API, the `[metrics]`/`[rubric]` task schema, and the `MetricConfig`/`AbsoluteThreshold`/`RegressionPolicy` types are stable. v1.1 only fills in the placeholders and adds the judge protocol.
- **Determinism/judged:** deterministic static/execution evaluators compare exactly (`max_worsening=0`); judged use a tolerance band (`≈0.1`) + n-sample averaging.

## Open decisions (confirm when v1.1 starts)

1. **Judge interface** — `score_criterion(criterion, artifact, n)` primitive + batch wrapper (recommended), vs. adapting `JudgedCriterion` to the batch ABC. Affects `evaluators/judged.py` + `evals/judge.py`.
2. **`[expected]` unification** — compile to BOOL evaluators (unified `grade()`) vs. keep `ExpectedOutcome` separate and merge results.
3. **Agent-runner scope** — which assistant runner(s) to implement first (`ClaudeCodeRunner` is the natural first target) and how the agent is invoked/sandboxed.
4. **`scratch_dir_state`** — what the runner captures and passes to the judge as `artifact` (diff? full tree? transcript?).
