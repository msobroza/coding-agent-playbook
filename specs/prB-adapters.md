## Shared patterns for all four tracks

### The `_default_cleanup` scan algorithm

The `Adapter` ABC's `_default_cleanup(written_paths, repo_root)` currently raises `NotImplementedError("lands with PR 6")`. **Track 6 (Continue) ships the real `_default_cleanup` implementation** on the ABC. Other adapters then either inherit it or override for adapter-specific paths.

**Shared algorithm** (lives on the ABC):

```python
def _default_cleanup(self, written_paths: set[Path], repo_root: Path) -> list[Path]:
    """Default cleanup: for each output directory this adapter knows about,
    walk the directory; for every file whose first line contains SENTINEL,
    if its absolute path is not in written_paths, delete it. Return the list
    of deleted paths.

    Subclasses tell the default scanner where to look by overriding
    ``_output_directories(repo_root) -> Iterable[Path]``. The Continue adapter
    returns ``[repo/.continue/rules, repo/.continue/prompts]``; the OpenCode
    adapter returns ``[repo/.opencode/command]``; etc.
    """
    deleted: list[Path] = []
    for output_dir in self._output_directories(repo_root):
        if not output_dir.is_dir():
            continue
        for path in output_dir.rglob("*"):
            if not path.is_file():
                continue
            if path.resolve() in written_paths:
                continue
            try:
                first_line = path.read_text(encoding="utf-8").split("\n", 1)[0]
            except (UnicodeDecodeError, OSError):
                continue
            if SENTINEL in first_line:
                path.unlink()
                deleted.append(path)
    return deleted
```

Each subclass defines `_output_directories(repo_root) -> Iterable[Path]`. Track 6 (Continue) does this refactor on the ABC.

**Sentinel detection:** the first line of every generated file must contain `SENTINEL` (the constant from `renderer.py`). For HTML-comment headers: `<!-- AUTOGENERATED by coding-agent-playbook ... -->`. For plain markdown: `# AUTOGENERATED by coding-agent-playbook ...`.

### Pre-rendered body input

`render_for(template_path, body, fmt, *, frontmatter, rule_registry=None)` is the single entry point each adapter uses. The adapter does NOT call Jinja itself — that's the renderer's job. The adapter:

1. Receives a `Rule` or `Prompt` (frontmatter dataclass + `body` already rendered through Jinja by the orchestrator in PR 10).
2. Calls `render_for(rule.source_path, rule.body, "continue_rule", frontmatter=rule.frontmatter.__dict__)` (or the appropriate `fmt` string).
3. Writes the returned string to the harness-specific path with a sentinel header.

For PR B's tests, you build `Rule`/`Prompt` instances inline (already-rendered bodies — just literal markdown) and pass them to the adapter. No need to involve the renderer or Jinja templates beyond what `render_for` consumes.
