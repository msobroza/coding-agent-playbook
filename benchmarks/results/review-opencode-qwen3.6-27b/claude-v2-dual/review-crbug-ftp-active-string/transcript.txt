## Correctness

- **`src/feedstorage.py:27`** — `settings["FEED_STORAGE_FTP_ACTIVE"] or False` treats the CLI string `"false"` as truthy, enabling active mode when the user explicitly requested it off. When the user passes `-s FEED_STORAGE_FTP_ACTIVE=false`, `from_command_line` stores the raw string `"false"`; `"false" or False` evaluates to `"false"`, which is truthy in the `if self.active:` guard on line 34, so `ftp.set_pasv(False)` fires and active mode turns **on**. The `Settings.getbool()` method (lines 36–45 of `settings.py`) exists precisely for this conversion and should be used: `settings.getbool("FEED_STORAGE_FTP_ACTIVE")`. — **important**

## Readability

- **`src/feedstorage.py:27`** — `or False` is dead code. The key `FEED_STORAGE_FTP_ACTIVE` is registered in `DEFAULTS` (settings.py line 10) and `Settings.__init__` merges DEFAULTS into `_values`, so `settings["FEED_STORAGE_FTP_ACTIVE"]` always returns a value (never `None`). The `or False` branch is unreachable. Replacing the whole expression with `settings.getbool("FEED_STORAGE_FTP_ACTIVE")` removes the dead fallback and fixes the correctness issue above in one change. — **nit**
