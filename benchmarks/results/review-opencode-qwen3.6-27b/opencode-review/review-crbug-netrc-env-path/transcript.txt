**Bug: `NETRC` env var path incorrectly prefixed with `~/`**

Line 17 in `src/netrc_auth.py:17`:

```python
loc = os.path.expanduser(f"~/{name}")
```

This always prepends `~/` to every location. When `NETRC` is set to an absolute path like `/etc/secrets/.netrc` (the common pattern), it resolves to `~/etc/secrets/.netrc` — a path that won't exist, so the function silently returns `None`.

The test passes because it sets `NETRC=.netrc-ci` (a bare filename), which happens to work with the `~/` prefix. It doesn't cover the absolute-path case that `NETRC` is typically used for.

**Fix**: Handle `NETRC` directly instead of routing it through the `~/` loop:

```python
netrc_file = os.environ.get("NETRC")
if netrc_file is not None:
    netrc_locations = (os.path.expanduser(netrc_file),)
else:
    netrc_locations = (f"~/{name}" for name in NETRC_FILES)
```
