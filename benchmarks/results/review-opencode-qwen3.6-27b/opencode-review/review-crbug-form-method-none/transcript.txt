**Bug: `AttributeError` when `method=None` is passed**

At `src/forms.py:43`:

```python
method = kwargs.pop("method", form.method).upper()
```

`dict.pop(key, default)` only returns the default when the key is **absent**. If `method=None` is explicitly passed as a kwarg, the key exists and `pop` returns `None`. Then `None.upper()` raises `AttributeError`.

This is a regression — the old code passed the raw value to `Request.__post_init__`, which had `(self.method or "GET").upper()` to handle `None` gracefully. The new code uppercases before any fallback, so `None` isn't caught.

Scenario: `FormRequest.from_form(form, method=None)` — or any caller that conditionally builds kwargs and includes `method=None` when no method was specified.

Fix:

```python
raw_method = kwargs.pop("method", form.method)
method = (raw_method or "GET").upper()
```
