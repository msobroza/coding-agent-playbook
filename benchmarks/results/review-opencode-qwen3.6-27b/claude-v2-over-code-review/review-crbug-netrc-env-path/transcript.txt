## Review: `get_netrc_auth` NETRC environment variable support

### 1. Correctness

- **`src/netrc_auth.py:17`** — **Absolute `NETRC` paths are mangled by unconditional `~/` prefix.** When `NETRC=/etc/custom_netrc`, the loop variable `name` is `/etc/custom_netrc`. Line 17 constructs `f"~/{name}"` → `~/etc/custom_netrc`, and `expanduser` turns that into `/Users/msobroza//etc/custom_netrc`, which doesn't exist. The function returns `None` instead of reading the intended file. This is the most common way to use `NETRC` (absolute CI paths like `/etc/ci/netrc`), so this breaks the primary use case. **Severity: important.**

- **`src/netrc_auth.py:12`** — **Empty `NETRC` string is not treated as unset.** When `NETRC=""`, `os.environ.get("NETRC")` returns `""`, which is not `None`, so `netrc_locations` becomes `("",)`. Line 17 then builds `f"~/"` → `expanduser("~/")` → the home directory itself. `os.path.exists` returns `True` for a directory, and the directory is passed to `netrc()` which raises `OSError`, silently swallowed by line 30. **Severity: important.**

- **`src/netrc_auth.py:17`** — **Tilde-prefixed `NETRC` values are double-prefixed.** When `NETRC=~/my_netrc`, line 17 constructs `~/~/my_netrc` → expanduser produces `/Users/msobroza/~/my_netrc`, which contains a literal `~` directory component and doesn't exist. **Severity: important.**

### 4. Design and Boundaries

- **`src/netrc_auth.py:11-17`** — **`NETRC` is treated as a filename inside `~/` rather than a full path.** Tools like `curl`, `git`, and Python's own `urllib` treat `NETRC` as the complete path to the netrc file. Treating it as a basename to be placed under `~` makes absolute paths, paths with `~` expansion, and relative paths outside the home directory all fail. The fix is to skip the `~/` prefix when the value comes from `NETRC`, or to use `NETRC` as the path directly. **Severity: important.**

### 5. Readability

- **`tests/test_netrc_auth.py:34`** — **Test only covers a relative `NETRC` path.** The test sets `NETRC=".netrc-ci"`, which exercises only the relative-path code path that happens to work. Adding a test with an absolute path (`monkeypatch.setenv("NETRC", str(tmp_path / ".netrc-ci"))`) would have caught the bug on line 17. **Severity: nit.**
