### 1. Correctness

- **`src/auth.py:16-17`** — **`important`** — `!` is not a valid Python operator. Lines 16-17 use `!hmac.compare_digest(...)` as if `!` were a logical NOT. Python has no `!` prefix operator; the correct spelling is `not`. As written, importing `src.auth` raises `SyntaxError` and the module is unusable.

- **`src/auth.py:16-17`** — **`important`** — Short-circuit `or` defeats the constant-time guarantee. Even after fixing the syntax to `not`, the expression `not hmac.compare_digest(username) or not hmac.compare_digest(password)` short-circuits: when the username does not match, the second `hmac.compare_digest` call is never reached. An attacker observing response time can still tell whether only the username was compared or both fields were compared, preserving the timing oracle the change intends to close. Both comparisons must execute regardless of the first result — for example, by storing each result in a variable and combining them after.

### 2. Failure modes

The `Credentials` dataclass annotates fields as `str` but does not enforce it at runtime. `Credentials(username=None, password="x")` constructs successfully, then `hmac.compare_digest(None, "admin")` raises `TypeError`. The original `!=` handled arbitrary objects gracefully (returning `True` for mismatch); this change turns a type-contract violation into a server error on the admin endpoint. Consider wrapping the comparison or validating the argument types before calling `hmac.compare_digest`.
