## 1. Correctness

- **`src/scene.py:36-38`** — The guard removes `new_m` before confirming `old_m` exists in the tree. If `old_m` is not found, `ValueError` is raised but `new_m` has already been silently removed from the scene. For example:

  ```
  scene.mobjects = [B, C]
  scene.replace(A, B)  # A doesn't exist
  ```

  The guard removes `B` from the list, the search fails, `ValueError` is raised, and `scene.mobjects` is now `[C]` — `B` is lost. The original behavior would raise while leaving the scene unchanged. This needs to be guarded: either remove only after confirming the replacement succeeded, or restore `new_m` on failure.

- **`src/scene.py:36-38`** — The guard only deduplicates within the same list. If `old_m` and `new_m` live in different groups at the same depth, `new_m` won't be removed from its group. Example: `group1.submobjects = [A]`, `group2.submobjects = [B]`; `replace(A, B)` yields `B` in both groups. This may be out of scope for the fix, but it's worth noting the deduplication is asymmetric (handles same-list and parent-vs-child, but not sibling groups).
