## Review: `CHANGE.diff` — Close the driver log output on quit

**Stated intent:** *Makes `Service.stop()` close the driver's log output on quit, whether `log_output` is an open file or a file descriptor, so no log file is left open once the driver stops.*

---

### Correctness

- **`src/service.py:37` — important — new** — `isinstance(self.log_output, TextIO)` does not match the file created when `log_output=None`. Line 23 opens `open(os.devnull, "wb")`, which produces a `BufferedRandom` (binary mode). That object is neither `TextIO` nor `int`, so neither `close()` nor `os.close()` fires and the devnull file handle leaks. Input: `Service("x").stop()` — the file opened on line 23 is never closed.

- **`src/service.py:37` — important — new** — Binary file objects passed directly as `log_output` also fall through both branches and leak. The old code's `hasattr(self.log_output, "close")` would have caught any closable object; the `isinstance(..., TextIO)` check is narrower than the caller contract promises. Input: `Service("x", log_output=open("f", "wb")).stop()` — `f` is never closed.

  **Suggestion:** Replace the type check with `hasattr(self.log_output, "close")` so it covers text files, binary files, and any duck-typed closable. Or, alternatively, open `os.devnull` in text mode (`"a"` instead of `"wb"`) and narrow the annotation — but `hasattr` is the safer, more general pattern.

The old code suppressed this with `except Exception: pass`. The new behavior (propagating the error) is generally better, but callers that treat `stop()` as fire-and-forget cleanup may now see unexpected exceptions. A narrow `except OSError: pass` around just this line preserves the cleanup intent without swallowing programming errors like `TypeError`.
