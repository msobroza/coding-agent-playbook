### Correctness

- **`src/forms.py:43`** — **important, new** — `kwargs.pop("method", form.method).upper()` raises `AttributeError` when `method=None` is passed as a keyword argument. `dict.pop("method", default)` returns `None` (the stored value), not the default, so `None.upper()` crashes. Previously the value flowed to `Request.__post_init__` which safely handled it with `(self.method or "GET").upper()`. Input: `FormRequest.from_form(form, method=None)`.

- **`src/forms.py:43`** — **important, new** — Same expression crashes when `form.method` is `None` and no `method` keyword is supplied. The default value of `pop()` is `form.method`, which at runtime can be `None` despite the type annotation. Previously `Request.__post_init__` converted `None` to `"GET"`. Input: `FormRequest.from_form(Form(action="/x", method=None))`.

### Design

- **`src/forms.py:33`** — **nit, new** — `valid_form_methods = ["GET", "POST"]` is a mutable list shared by every instance and subclass. A one-off mutation like `FormRequest.valid_form_methods.append("PUT")` silently widens the allowlist for all callers. Use an immutable tuple `("GET", "POST")` to prevent accidental shared-state bugs.

- **`src/forms.py:43` / `src/forms.py:27`** — **nit, new** — The method is uppercased at line 43, then uppercased again by `Request.__post_init__` at line 27. Harmless, but now redundant due to this change.
