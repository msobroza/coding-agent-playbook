The config docstring (line 3-4) explicitly documents: *"a string of ordinary ffmpeg arguments"*. The `or` chain: `parse_preset_input(ffmpeg_input.input_args, 1)` returns `None` (not a preset name), then `or ffmpeg_input.input_args` yields the raw string `"-rtsp_transport udp"` (truthy, so the chain stops). Result: `get_ffmpeg_arg_list(ffmpeg.global_args) + "-rtsp_transport udp"` → `TypeError: can only concatenate list (not "str") to list`. Input: any `input_args` value that is a non-empty string not matching a preset name — which is exactly what the config docs say is valid.

- **`src/audio.py:15-20` — `important`** — Same `TypeError` when both `ffmpeg_input.input_args` and `ffmpeg.input_args` are empty strings (`""`). Trace: `parse_preset_input("", 1)` → `None`, `or ""` → falsy so continue, `parse_preset_input("", 1)` → `None`, `or ""` → `""` is the final result. Then `list + ""` → `TypeError`. Input: both `input_args` fields set to `""`. Note that `FfmpegConfig.input_args` defaults to `"preset-rtsp-generic"`, so this requires the user to explicitly set both to `""`, but the config type (`FfmpegArgs = str | list[str]`) permits it.

- **`src/audio.py:14` — `pre-existing`** — `IndexError` when no input has the `"audio"` role. `[i for i in ffmpeg.inputs if "audio" in i.roles][0]` on an empty list. Input: any `FfmpegConfig` whose inputs lack an `"audio"` role. The old code had the same crash in `AudioEventMaintainer.__init__`, but only called from that constructor (which is presumably only constructed for audio-enabled cameras). Now `get_ffmpeg_command` is a standalone function callable with any config — the crash surface widened.
