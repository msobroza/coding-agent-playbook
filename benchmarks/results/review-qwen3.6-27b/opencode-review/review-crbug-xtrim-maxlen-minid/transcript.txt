**Bug: `maxlen` and `minid` are not mutually exclusive**

Redis `XTRIM` accepts exactly one strategy: `MAXLEN` or `MINID`. The current code allows both, producing:

```
XTRIM events MAXLEN MINID ~ 100 1700000000000-0
```

This is syntactically invalid and will be rejected by the server. Add a guard:

```python
if maxlen is None and minid is None:
    raise ValueError("at least one of maxlen or minid is required")
if maxlen is not None and minid is not None:
    raise ValueError("maxlen and minid are mutually exclusive")
```

No test covers this case. Add one that expects `ValueError` when both are provided.
