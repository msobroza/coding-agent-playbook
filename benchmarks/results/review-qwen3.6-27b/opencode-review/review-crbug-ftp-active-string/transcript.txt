**Bug: `from_settings` bypasses `getbool`, breaking command-line string overrides**

`src/feedstorage.py:27` reads the setting with `settings["FEED_STORAGE_FTP_ACTIVE"] or False`. When the setting is set via command line (`-s FEED_STORAGE_FTP_ACTIVE=false`), `Settings.from_command_line` stores it as the raw string `"false"`. The expression `"false" or False` evaluates to `"false"` (truthy non-empty string), so **active mode is incorrectly enabled** even though the user explicitly requested passive mode.

`src/settings.py:36` already has `getbool()` to handle this — it converts `"true"`/`"false"` strings, `1`/`0`, and native booleans correctly. The fix is:

```python
return cls(host, path, active=settings.getbool("FEED_STORAGE_FTP_ACTIVE", False))
```
