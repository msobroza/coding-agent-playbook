**Line 17**: `os.path.expanduser(f"~/{name}")` always prepends `~/`. If `NETRC=/tmp/.netrc`, the loop constructs `~/tmp/.netrc` → expands to `/home/user/tmp/.netrc`. Absolute paths from `NETRC` are silently mangled.

**Line 11**: `if netrc_file is not None` passes through `""`. If `NETRC=""`, then `name=""` and `loc` becomes `os.path.expanduser("~/")` (the home directory itself), which `os.path.exists()` treats as existing, then `netrc(home_dir)` fails.

The test at line 34 only exercises a bare filename (`.netrc-ci`), so the absolute-path bug is untested.

- **src/netrc_auth.py:17** — correctness — `important` — `os.path.expanduser(f"~/{name}")` unconditionally prepends `~/`, mangling absolute `NETRC` paths. `NETRC="/tmp/.netrc"` becomes `~/tmp/.netrc` → `/home/user/tmp/.netrc`. Standard convention (curl, git, wget) treats `NETRC` as the file path directly.
- **src/netrc_auth.py:11** — correctness — `important` — `if netrc_file is not None` treats empty string as valid. `NETRC=""` produces `name=""` so `loc` becomes `os.path.expanduser("~/")` (the home directory), which `os.path.exists()` returns `True` for, then `netrc(home_dir)` crashes. Check for empty string too: `if netrc_file` or `if netrc_file is not None and netrc_file`.
- **src/netrc_auth.py:17** — correctness — `important` — Even non-absolute, non-bare-filename values like `NETRC="subdir/.netrc"` or `NETRC="./local/.netrc"` produce wrong paths (`~/subdir/.netrc` instead of `./local/.netrc`). The loop body only works for bare filenames; it can't handle relative paths from the working directory.
