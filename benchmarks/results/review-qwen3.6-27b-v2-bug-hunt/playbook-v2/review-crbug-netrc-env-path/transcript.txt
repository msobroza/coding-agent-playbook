The critical issue is at line 17: when `NETRC` holds an absolute path (the most common real-world usage, e.g., `NETRC=/etc/netrc` or `NETRC=$GITHUB_HOME/.netrc`), the loop always prepends `~/`:


With `name="/etc/netrc"`, this becomes `os.path.expanduser("~//etc/netrc")` → `/home/user//etc/netrc`. Wrong path, no credentials found.

**Correctness**

- **src/netrc_auth.py:17 — `important`** — `os.path.expanduser(f"~/{name}")` prepends `~/` to every entry in `netrc_locations`, including the value from `NETRC`. When `NETRC` is an absolute path like `/etc/netrc`, this produces `~//etc/netrc` which expands to `$HOME//etc/netrc`, a non-existent path. The standard convention (Python's `netrc` module, curl, GNU wget) is that `NETRC` holds the file path directly. The loop should use absolute `NETRC` values as-is.

- **src/netrc_auth.py:12 — `important`** — `netrc_file is not None` treats the empty string as a valid path. When `NETRC=""`, `os.environ.get("NETRC")` returns `""` (not `None`), so `netrc_locations` becomes `("",)`. The loop then computes `os.path.expanduser("~/")` which resolves to `$HOME` — a directory. `os.path.exists("$HOME")` is `True`, so `netrc("$HOME")` is called, raising `NetrcParseError` (silently swallowed when `raise_errors=False`) or crashing when `raise_errors=True`. Use `if netrc_file` instead of `if netrc_file is not None`.
