## Correctness

- **src/auth.py:16** — `important` — `!hmac.compare_digest(...)` uses `!` as a negation operator. Python has no `!` unary operator; the correct form is `not`. This raises `SyntaxError: invalid syntax` on import, making the entire module unloadable.

## Security

- **src/auth.py:16-17** — `important` — Even after fixing the syntax error to `not`, the `or` between the two negated comparisons short-circuits: when the username does not match, `not hmac.compare_digest(given.username, expected.username)` is `True`, so the password comparison is never executed. This means the function still leaks whether the username was correct through timing, defeating the stated goal. Both credential fields must be compared before any decision is made. The fix is to combine both comparisons under a single `hmac.compare_digest` call (e.g., comparing `username + separator + password`), or to evaluate both `hmac.compare_digest` calls and combine the results with `and` instead of short-circuiting with `or`.

- **src/auth.py:17 (original line, not in diff)** — `pre-existing` — The original `!=` comparison on the old line 17 (`given.username != expected.username or given.password != expected.password`) also short-circuits on `or`, leaking whether the username matched before the password was even checked. This change does not address the fundamental structural need to always compare both fields.
