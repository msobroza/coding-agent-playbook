**Key analysis notes:**
- Redis 6.2 parses `~` only in the MAXLEN branch (`if !strcasecmp(argv[2],"maxlen") ... if !strcasecmp(argv[3],"~")`). For MINID, `argv[3]` is parsed as the stream ID — so `XTRIM key MINID ~ id` fails with `ERR Invalid stream ID specified as minId`. MINID trimming is exact-only per the Redis docs.
- Old signature made `maxlen` required; the new one makes both strategies optional with no "at least one" guard.
- Both strategies can be emitted simultaneously with no mutual-exclusion check.
- `LIMIT 0`/negative is rejected server-side; no validation.
- `maxlen=0` is handled correctly (`is not None`), and the MAXLEN wire order (`MAXLEN ~ 100 LIMIT 10`) is valid — no false positives there.
