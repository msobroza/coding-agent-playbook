## Review of CHANGE.diff (`FormRequest.from_form` method whitelisting)

**Scope:** `src/forms.py` — `from_form` now uppercases the method and falls back to `"GET"` when it's not in `["GET", "POST"]`; `tests/test_forms.py` — three new tests.

**Method:** All 8 finder angles run in-context; every behavioral claim runtime-verified against the working tree (probe script run and removed; suite: 6/6 passed). No CLAUDE.md exists anywhere in the repo, so the conventions angle yields nothing.

**Key context that makes the bugs real:**
- `Request` (line 20) documents "a missing method means GET"; its field is `method: str | None` and `__post_init__` (line 27) does `self.method = (self.method or "GET").upper()`. So **None is a first-class state in this codebase**, and the pre-change line `method = kwargs.pop("method", form.method)` safely delegated None to `__post_init__`. The diff's new `.upper()` removed that safe path.
- `Form.method` is annotated `str` but unenforced; a parser mirroring a `<form>` with no `method` attribute (valid HTML — GET is the default) yields `None`.
- `from_form`'s docstring promises the `method` keyword "overrides the form's".

**Verified behaviors:**
- `FormRequest.from_form(Form(action="/x", method=None, fields={"a":"b"}))` → `AttributeError: 'NoneType' object has no attribute 'upper'`
- `FormRequest.from_form(Form(action="/x", method="post"), method=None)` → same `AttributeError`
- `FormRequest.from_form(..., method="PATCH")` → `method='GET'`, form data still attached
- `method="pOsT"` → `"POST"`, `""` → `"GET"`, `"DELETE"` → `"GET"`, `"post"` → `"POST"` (all correct)
- No test exercises the None path, so the suite is green despite the crash.
